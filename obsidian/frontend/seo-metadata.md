# SEO & Metadata

## Site config

`src/lib/site.ts` (`siteConfig`) is the **single source of truth** for SEO **and
authorship** — name, `tagline`, description, origin URL, OG image, `author`,
`authorUrl`, `year`, `conceptNote`, theme colour. The metadata generator,
`robots.ts`, `sitemap.ts`, the JSON-LD helper, and the footer credit all read from
it. Wired to the **Stride** brand ("Modern banking for people and businesses") —
`name: "Stride"`, a `tagline` field (used for the homepage `<title>`), a
concept-framed description, `themeColor: #04070f` (the dark hero backdrop the page
opens on).

It also exports the shared **`SiteLink`** type (`{ label, href, external? }`) used
by the nav, the hero CTAs, and the footer columns — so every clickable label in the
page carries its destination as content, never a hardcoded `href="#"`.

> [!important] Stride is a fictional brand
> There is **no `twitterHandle`** and no invented contact details anywhere — a
> made-up `@handle` points at somebody else's account and a made-up `mailto:`/`tel:`
> is a dead link. `authorUrl` is intentionally empty until a real profile URL exists;
> the footer credit degrades to plain text rather than rendering a dead anchor. See
> [[decisions-log]] ADR-0017.

`siteConfig.url` comes from `NEXT_PUBLIC_SITE_URL` (see [[environment-variables]]),
falling back to `http://localhost:3000`.
`siteConfig.url` falls back to the **production origin**
(`https://stridebanking.vercel.app`), *not* localhost. An unset `NEXT_PUBLIC_SITE_URL`
previously shipped `http://localhost:3000` into `metadataBase` and therefore into every
canonical, `og:url`, `og:image` and JSON-LD `@id` in the deployed page source. A dev
build emitting production URLs is harmless; the reverse silently breaks link previews
and canonical tags. `NEXT_PUBLIC_SITE_URL` is set on Vercel (Production + Preview) so a
custom domain can override it without a code change.

## Metadata generator

`src/utils/seo/generate-page-metadata.ts` exports two builders:

```ts
import {
  generateMetadata,
  generateViewport,
} from "@/utils/seo/generate-page-metadata";

export const metadata = generateMetadata({ title: "…", description: "…" });
export const viewport = generateViewport();
```

- `generateMetadata(props?)` → a Next.js `Metadata` object: title/description,
  OpenGraph, Twitter cards, canonical, icons, robots. `metadataBase` is **always
  set** from `siteConfig.url`, so relative URLs (OG image, canonical) resolve to
  absolute — required by social scrapers.
- `generateViewport()` → the `Viewport` export. `themeColor` lives here, **not**
  on the metadata object (Next deprecated it there).

Accepted `generateMetadata` options: `title`, `description`, `url`, `ogImage`,
`author`, `siteName`. (`keywords` and the non-standard `other` tags were dropped —
no SEO value; `twitterHandle` was dropped with ADR-0017 — the Twitter card still
emits `card`/`title`/`description`/`images`, just no `site`/`creator` handle.)

## robots.txt & sitemap.xml

Generated by the Next file conventions:
- `src/app/robots.ts` → `/robots.txt` — allows all crawlers, points at the sitemap.
- `src/app/sitemap.ts` → `/sitemap.xml` — lists public routes (home only so far;
  add an entry per route as the site grows).

## Structured data (JSON-LD)

`src/utils/seo/structured-data.ts` → `getSiteStructuredData()` builds a
**`Person`** (the author) + **`CreativeWork`** (the concept itself — `genre`,
`abstract`, `copyrightYear`, `author`/`creator`) + **`WebSite`** JSON-LD graph,
linked by `@id`. The root layout renders it once in a
`<script type="application/ld+json">`.

**Not `Organization`** — Stride is fictional, and `Organization` schema asserts a
company that does not exist (it can surface in knowledge panels). `CreativeWork`
by a `Person` is what a concept piece actually is. See [[decisions-log]] ADR-0017.

The root layout (`app/layout.tsx`) overrides the homepage `<title>` with
`"${siteConfig.name} — ${siteConfig.tagline}"` (keyword-rich); subpages pass their
own `title` to `generateMetadata`.

## Bot detection

`src/utils/is-bot.ts` exports `isBot()` — a **server-only** async helper that
reads the `user-agent` header and returns `true` for Lighthouse, Googlebot,
PageSpeed, HeadlessChrome, GTmetrix, Pingdom, Bingbot, Yandexbot.

> [!caution]
> Calling `isBot()` (or any `headers()` reader) in a route **opts it out of
> static prerendering** — a TTFB cost for every visitor. Serving crawler-specific
> behaviour also borders on cloaking. Prefer the [[animation-system|reduced-motion]]
> path (`<ReducedMotion>`): animations only touch opacity/transform, so content
> is always in the DOM and crawlers see it regardless. Use `isBot()` sparingly.

## Static assets

The `public/` **root** holds meta/PWA/SEO assets — favicons (multiple sizes),
Android/Apple icons, `manifest.json`, `open-graph.png`. (`browserconfig.xml` was
deleted: nothing referenced it — there is no `msapplication-config` meta tag — and
the three `ms-icon-*.png` tiles it pointed at were never in `public/`.)
Site **content** assets (images, videos) go under `public/assets/<section>/` —
see [[folder-structure]].

`open-graph.png` is **1200×630** — the size LinkedIn, X, Slack, iMessage and
Facebook render as a full-width card (below it they fall back to a small square
thumbnail). It is a 2× capture of the production hero, downscaled to exactly 1200×630;
regenerate it the same way after any hero change. `generate-page-metadata.ts` declares
matching `width`/`height`.
